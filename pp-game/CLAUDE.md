# pp — 프로젝트 규칙

체리필터 '피아니시모'의 정서를 바탕으로 한 웹 스토리 퍼즐 게임. 개발자(Toby)는 게임 개발이 처음이다.

## 먼저 읽을 것
- `docs/design.md` — 기획 전체 (세계관, 반전, 복선, 챕터, 기믹, 아트, 로드맵, 미결 사항). 작업 전에 항상 관련 부분을 확인한다
- `prototype/pp-prototype.html` — 확정된 손맛의 기준이 되는 원본 프로토타입. 새 코드로 옮길 때 조작감·연출이 이것보다 나빠지면 안 된다

## 소통 방식
- 한국어로 답한다. 전문 용어는 처음 나올 때 쉬운 말로 풀어 준다
- 명령어를 실행해야 하면 무엇을 왜 하는지 한 줄로 설명한다
- 작업 단위가 끝나면 **멈추고**: 무엇을 바꿨는지, 브라우저에서 무엇을 확인하면 되는지 정리한 뒤 확인을 기다린다. "다음"이라고 하기 전에는 다음 단계로 넘어가지 않는다
- 기획과 다른 판단이 필요하면 임의로 정하지 말고 물어본다. 결정이 나면 `docs/design.md`를 갱신한다
- 새 아이디어가 나오면 바로 구현하지 말고 `docs/ideas.md`에 적어 둔다

## 기술 규칙
- TypeScript + Vite. 외부 라이브러리는 꼭 필요할 때만, 추가 전에 이유를 말한다
- 실행: `npm install` 후 `npm run dev` → 브라우저에서 표시된 localhost 주소 확인
- 오디오는 Web Audio API. 사용자 클릭 후에만 소리를 시작한다
- 모듈 구분 예시: `input/`(드래그·키 코드), `audio/`(음색·편곡), `render/`(수묵·이펙트), `world/`(맵·오브젝트), `story/`(대사·챕터 진행), `data/`(코드·챕터 정의)
- 코드·대사·챕터 데이터는 분리한다 (대사와 퍼즐 정의는 데이터 파일로)
- 커밋은 작업 단위마다, 메시지는 한국어로 무엇을 했는지 짧게

## 아트·연출 원칙
- "먹과 형광": 평소 먹 90% · 형광 10%. 형광(핫핑크·노랑)은 ff, 후렴, F 코드, 기타 솔로 같은 클라이맥스에만
- 한지 질감, 먹의 농담, 넓은 여백. 강한 순간엔 먹 스플래시·섬광·집중선·화면 흔들림
- `prefers-reduced-motion`이면 흔들림·섬광을 줄인다

## 저작권 원칙 (반드시 지킨다)
- 원곡 가사를 게임 텍스트·코드·데이터에 그대로 넣지 않는다. 대사와 문구는 모두 오리지널로 쓴다
- 앨범 커버의 캐릭터·디자인을 재현하지 않는다. 톤과 구도의 느낌만 참고하고 모든 그림은 오리지널
- 원곡 음원(inst) 파일은 저장소에 커밋하지 않는다 (`.gitignore`). 사용 여부는 추후 저작권 검토 후 결정
